    声明切点

    切面点用于确定感兴趣的连接点，从而使我们能够控制何时执行通知。Spring AOP 仅支持 Spring bean 的方法执行连接点，因此您可以将切面点视为匹配在 Spring bean 上方法执行的执行。切面点声明包含两部分：一个由名称和任何参数组成的签名，以及一个确定我们确切感兴趣哪些方法执行的切面点表达式。在 @AspectJ 注解风格的 AOP 中，切面点签名由常规方法定义提供，而切面点表达式通过使用 @Pointcut 注解来指示（作为切面点签名的方法必须具有 void 返回类型）。

    一个示例有助于阐明切入点签名与切入点表达式之间的区别。以下示例定义了一个名为anyOldTransfer的切入点，用于匹配任何名为transfer的方法的执行：

    • Java

    • Kotlin

    @Pointcut("execution(* transfer(..))") // the pointcut expression
private void anyOldTransfer() {} // the pointcut signature
    @Pointcut("execution(* transfer(..))") // the pointcut expression
private fun anyOldTransfer() {} // the pointcut signature

    `@Pointcut` 注解的值由一个点切面表达式形成，该表达式是标准的 AspectJ 点切面表达式。关于 AspectJ 点切面语言的完整讨论，请参阅 AspectJ 编程指南（以及关于扩展内容的 AspectJ 5 开发者笔记），或者 AspectJ 的相关书籍（例如 Colyer 等人著的 Eclipse AspectJ，或 Ramnivas Laddad 著的 AspectJ in Action）。

    支持的切点设计符

    Spring AOP 支持以下 AspectJ 点切面设计符（PCD），可用于点切面表达式：

    • execution：用于匹配方法执行连接点。这是在使用 Spring AOP 时应使用的主要切入点设计符。

    • within：将匹配限制在特定类型的连接点内（在使用 Spring AOP 时，指匹配类型中声明的方法的执行）。

    • this：将匹配限制为连接点（在使用 Spring AOP 时方法的执行），其中 Bean 引用（Spring AOP 代理）是指定类型的实例。

    • target：将匹配限制为连接点（在使用 Spring AOP 时方法的执行），其中目标对象（被代理的应用程序对象）是指定类型的实例。

    • args：将匹配限制为连接点（在使用 Spring AOP 时方法的执行），其参数是指定类型的实例。

    • @target：将匹配限制为连接点（在使用 Spring AOP 时方法的执行），其中执行对象的类具有给定类型的注解。

    • @args：将匹配限制为连接点（在使用 Spring AOP 时方法的执行），其中实际传递参数的运行时类型具有给定类型的注解。

    • @within：将匹配限制在具有给定注解的类型内的连接点（在使用 Spring AOP 时，即执行具有给定注解的类中声明的方法）。

    • @annotation：将匹配限制在具有给定注解的切入点主体（Spring AOP 中正在运行的方法）所在的连接点上。

    其他切点类型

    完整的 AspectJ 点切面语言支持 Spring 不支持的额外点切面设计符：call、get、set、preinitialization、staticinitialization、initialization、handler、adviceexecution、withincode、cflow、cflowbelow、if、@this 和 @withincode。在 Spring AOP 解释的点切面表达式中使用这些点切面设计符会导致抛出 IllegalArgumentException。

    Spring AOP 支持的点切面设计符集合可能会在未来的版本中扩展，以支持更多的 AspectJ 点切面设计符。

    由于 Spring AOP 将匹配范围限制为仅方法执行连接点，前述关于切入点设计符的讨论给出的定义比 AspectJ 编程指南中的定义更窄。此外，AspectJ 本身具有基于类型的语义，在执行连接点处，this和target都指向同一个对象：即正在执行该方法的对象。Spring AOP 是一个基于代理的系统，它区分代理对象本身（绑定到this）和代理背后的目标对象（绑定到target）。

    由于 Spring AOP 框架基于代理，目标对象内部的调用按定义不会被拦截。对于 JDK 代理，只有对代理的公共接口方法调用可以被拦截。使用 CGLIB 时，对代理的公共和受保护方法调用会被拦截（必要时甚至包括包可见方法）。然而，通过代理进行的常见交互应始终通过公共签名进行设计。

    注意，切面定义通常与任何拦截的方法进行匹配。如果切面严格限定为仅公开（public），即使在可能存在通过代理的非公开交互的 CGLIB 代理场景中，也需要相应地定义它。

    如果您的拦截需求包括目标类中的方法调用甚至构造函数，请考虑使用 Spring 驱动的 原生 AspectJ 织入，而不是基于代理的 Spring AOP 框架。这构成了 AOP 使用的不同模式，具有不同的特性，因此在做出决定之前，请务必熟悉织入技术。

    Spring AOP 还支持一个名为bean的额外 PCD。此 PCD 允许您将连接点的匹配限制为特定的命名 Spring bean，或一组命名的 Spring bean（在使用通配符时）。bean PCD 具有以下形式：

    bean(idOrNameOfBean)

    idOrNameOfBean 标记可以是任何 Spring Bean 的名称。提供了使用 * 字符的有限通配符支持，因此，如果您为 Spring Bean 建立了一些命名约定，则可以编写一个 bean PCD 表达式来选择它们。与其他切入点设计器一样，bean PCD 也可以与 &&（与）、||（或）和 !（否定）运算符一起使用。

    bean 类型的 PCD 仅受 Spring AOP 支持，而不支持原生 AspectJ 织入。它是 Spring 对 AspectJ 定义的标准 PCD 的特定扩展，因此对于在 @Aspect 模型中声明的切面不可用。

    bean PCD 在实例级别运行（基于 Spring bean 名称概念），而不仅仅局限于类型级别（基于织造的 AOP 仅限于此）。基于实例的点切面设计符是 Spring 代理式 AOP 框架的特殊功能，该框架与 Spring Bean 工厂紧密集成，在此环境中通过名称识别特定 bean 既自然又直接。

    组合切点表达式

    您可以使用&&、||和!组合切点表达式。您也可以按名称引用切点表达式。以下示例展示了三个切点表达式：

    • Java

    • Kotlin

    package com.xyz;

public class Pointcuts {

	@Pointcut("execution(public * *(..))")
	public void publicMethod() {} (1)

	@Pointcut("within(com.xyz.trading..*)")
	public void inTrading() {} (2)

	@Pointcut("publicMethod() && inTrading()")
	public void tradingOperation() {} (3)
}
    1 publicMethod 匹配任何公共方法的执行连接点。
    2 inTrading 匹配在交易模块中的方法执行。
    3 tradingOperation 匹配交易模块中任何公共方法的方法执行。 
    package com.xyz

class Pointcuts {

	@Pointcut("execution(public * *(..))")
	fun publicMethod() {} (1)

	@Pointcut("within(com.xyz.trading..*)")
	fun inTrading() {} (2)

	@Pointcut("publicMethod() && inTrading()")
	fun tradingOperation() {} (3)
}
    1 publicMethod 匹配任何公共方法的执行连接点。
    2 inTrading 匹配在交易模块中的方法执行。
    3 tradingOperation 匹配交易模块中任何公共方法的方法执行。

    将更复杂的切入点表达式构建为较小的命名切入点是一种最佳实践，如上所示。当通过名称引用切入点时，适用正常的 Java 可见性规则（您可以在同一类型中看到private切入点，在层次结构中查看protected切入点，在任何位置查看public切入点等）。可见性不影响切入点的匹配。

    共享命名切面定义

    在处理企业级应用程序时，开发人员经常需要从多个方面引用应用程序的模块和特定的操作集。我们建议定义一个专用类来捕获常用的 命名切点 表达式，以便实现此目的。此类通常类似于以下 CommonPointcuts 示例（尽管类的名称由您自行决定）：

	 * in a type in the com.xyz.web package or any sub-package
	 * under that.

	 * A join point is in the service layer if the method is defined
	 * in a type in the com.xyz.service package or any sub-package
	 * under that.
	 */

	 * under that.
	 */

	 *

    Examples

    Spring AOP 用户最有可能频繁使用execution切入点设计符。 execution 表达式的格式如下：

    execution(modifiers-pattern?
			ret-type-pattern
			declaring-type-pattern?name-pattern(param-pattern)
			throws-pattern?)

    除了返回类型模式（前例中的ret-type-pattern）、名称模式和参数模式外，其余部分均为可选。返回类型模式决定了方法必须具有何种返回类型才能匹配连接点。*最常用作返回类型模式，它匹配任何返回类型。完全限定的类型名仅当方法返回该给定类型时才匹配。名称模式匹配方法名。您可以使用*通配符作为名称模式的全部或部分。如果指定了声明类型模式，请在末尾包含一个.将其与名称模式组件连接起来。参数模式稍显复杂：()匹配不接受任何参数的方法，而(..)匹配任意数量（零个或多个）的参数。(*)模式匹配接受一个任意类型参数的方法。(*,String)匹配接受两个参数的方法：第一个可以是任意类型，而第二个必须是String。有关更多信息，请参阅 AspectJ 编程指南中的语言语义部分。

    以下示例展示了一些常见的切点表达式：

    • 任何公共方法的执行：

      execution(public * *(..))

    • 执行任何以set开头的名称的方法：

      execution(* set*(..))

    • AccountService 接口中定义的任意方法的执行：

      execution(* com.xyz.service.AccountService.*(..))

    • service 包中定义的任意方法的执行：

      execution(* com.xyz.service.*.*(..))

    • service 包或其任一子包中定义的任意方法的执行：

      execution(* com.xyz.service..*.*(..))

    • 服务包内的任何连接点（在 Spring AOP 中仅指方法执行）：

      within(com.xyz.service.*)

    • 服务包或其任一子包内的任何连接点（在 Spring AOP 中仅指方法执行）：

      within(com.xyz.service..*)

    • 任何代理实现了 AccountService 接点的连接点（在 Spring AOP 中仅指方法执行）：

      this(com.xyz.service.AccountService)
      this 更常用于绑定形式。请参阅声明 Advice部分，以了解如何在 Advice 主体中提供代理对象。

    • 任何目标对象实现了AccountService接口的连接点（在 Spring AOP 中仅指方法执行）：

      target(com.xyz.service.AccountService)
      target 在绑定形式中更常用。请参阅声明 Advice部分，以了解如何在 Advice 主体中提供目标对象。

    • 任何只接受单个参数且在运行时传入的参数为Serializable的连接点（在 Spring AOP 中仅指方法执行）：

      args(java.io.Serializable)
      args 在绑定表单中更常用。请参阅声明 Advice部分，了解如何在 Advice 主体中使方法参数可用。

      请注意，本示例中给出的切入点与 execution(* *(java.io.Serializable)) 不同。args 版本在运行时传递的参数是 Serializable 时匹配，而 execution 版本在方法签名声明单个类型为 Serializable 的参数时匹配。

    • 任何目标对象具有@Transactional注解的 JoinPoint（在 Spring AOP 中仅指方法执行）：

      @target(org.springframework.transaction.annotation.Transactional)
      在绑定形式中，您也可以使用 @target。有关如何在建议主体中使注解对象可用，请参阅声明建议部分。

    • 任何目标对象的声明类型具有@Transactional注解的切点（在 Spring AOP 中仅指方法执行）：

      @within(org.springframework.transaction.annotation.Transactional)
      在绑定形式中，您也可以使用 @within。有关如何在建议主体中使注解对象可用，请参阅声明建议部分。

    • 任何执行方法带有@Transactional注解的切点（在 Spring AOP 中仅指方法执行）：

      @annotation(org.springframework.transaction.annotation.Transactional)
      在绑定形式中也可以使用 @annotation。请参阅声明 Advice部分，以了解如何在 Advice 主体中提供注解对象。

    • 任何仅接受单个参数的连接点（在 Spring AOP 中仅为方法执行），且传入参数的运行时类型带有@Classified注解：

      @args(com.xyz.security.Classified)
      在绑定表单中也可以使用 @args。请参阅声明 Advice部分，了解如何在 Advice 主体中提供注解对象。

    • 任何在名为tradeService的 Spring bean 上的连接点（Spring AOP 中仅指方法执行）：

      bean(tradeService)

    • 任何匹配通配符表达式*Service的 Spring bean 名称上的连接点（在 Spring AOP 中仅指方法执行）：

      bean(*Service)

    编写良好的切点

    在编译期间，AspectJ 会按顺序处理切入点（pointcuts）以优化匹配性能。检查代码并确定每个连接点（join point）是否（静态地或动态地）匹配给定的切入点是一个耗时的过程。（动态匹配意味着无法仅通过静态分析完全确定匹配结果，因此需要在代码中放置测试，以便在代码运行时确定是否存在实际匹配）。首次遇到切入点声明时，AspectJ 会将其重写为适合匹配过程的最优形式。这意味着什么？基本上，切入点会被重写为析取范式（DNF, Disjunctive Normal Form），并且切入点的组件会被排序，使得成本较低的组件优先进行检查。这意味着您无需担心理解各种切入点设计符的性能，可以在切入点声明中以任意顺序提供它们。

    然而，AspectJ 只能根据所告知的内容工作。为了获得最佳匹配性能，您应思考要实现的目标，并在定义中尽可能缩小匹配的搜索空间。现有的设计符自然地分为三类：种类限定符、作用域限定符和上下文限定符：

    • Kinded 设计符选择特定类型的连接点：execution、get、set、call 和 handler。

    • 作用域设计符用于选择一组感兴趣的重入点（可能包含多种类型）：within 和 withincode。

    • 上下文设计符根据上下文进行匹配（并可选地绑定）：this、target 和 @annotation。

    编写良好的切面点应至少包含前两种类型（即 kinded 和 scoping）。您可以包含上下文设计符以根据连接点上下文进行匹配，或将该上下文绑定以便在Advice中使用。仅提供 kinded 设计符或仅提供上下文设计符虽然可行，但由于需要额外的处理和解析，可能会影响织入性能（时间和内存使用）。Scoping 设计符的匹配速度非常快，使用它们意味着 AspectJ 可以非常迅速地排除不应进一步处理的一组连接点。如果可能的话，良好的切面点应始终包含一个 scoping 设计符。
