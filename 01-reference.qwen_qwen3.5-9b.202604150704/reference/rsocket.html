    RSocket

    本节描述了 Spring Framework 对 RSocket 协议的支持。

    Overview

    RSocket 是一种用于在 TCP、WebSocket 和其他字节流传输上实现多路复用双向通信的应用层协议，使用以下交互模型之一：

    • 请求 - 响应 — 发送一条消息并接收一条返回。

    • Request-Stream — 发送一条消息并接收返回的消息流。

    • Channel — 双向发送消息流。

    • Fire-and-Forget — 发送单向消息。

    一旦建立初始连接，"客户端"与"服务器"的区别即消失，因为双方变得对称，每一方都可以发起上述交互之一。这就是为什么在协议调用中，参与方被称为"请求者"(requester)和"响应者"(responder)，而上述交互被称为"请求流"(request streams)或简称为"请求"(requests)。

    这是 RSocket 协议的关键特性和优势：

    • Reactive Streams 语义跨越网络边界——对于诸如 Request-Stream 和 Channel 之类的流式请求，反向压力信号在请求者和响应者之间传输，允许请求者在源头减缓响应者的速度，从而减少对网络层拥塞控制的依赖，以及减少在网络层或任何层级进行缓冲的需求。

    • 请求节流——此功能命名为“租赁（Leasing）”，得名于每个端点可发送的 LEASE 帧，该帧用于限制对方在给定时间内允许的其他端点的总请求数。租约会定期续期。

    • 会话恢复——此功能旨在应对连接中断，需要维护一定的状态。状态管理对应用程序是透明的，并且与背压机制配合良好；背压可以在可能时停止生产者，从而减少所需的状态量。

    • 大型消息的分片和重组。

    • Keepalive (heartbeats).

    RSocket 在多种语言中都有实现。Java 库基于Project Reactor构建，并使用Reactor Netty作为传输层。这意味着您应用程序中 Reactive Streams Publishers 发出的信号可以透明地通过 RSocket 在网络上传播。

    协议

    RSocket 的优势之一在于其具有明确的传输层行为、易于阅读的规范以及一些协议扩展。因此，无论语言实现和高级框架 API 如何，阅读该规范都是一个很好的主意。本节提供了一个简洁的概述以建立一些背景。

    Connecting

    最初，客户端通过某种低级流式传输（如 TCP 或 WebSocket）连接到服务器，并发送一个SETUP帧以设置连接参数。

    服务器可能会拒绝SETUP帧，但通常在该帧被发送（对于客户端）并接收（对于服务器）之后，双方都可以开始发起请求，除非SETUP指示使用租约语义来限制请求数量，在这种情况下，双方必须等待对方发来的LEASE帧以允许发起请求。

    发起请求

    一旦连接建立，双方均可通过以下帧之一发起请求：REQUEST_RESPONSE、REQUEST_STREAM、REQUEST_CHANNEL 或 REQUEST_FNF。这些帧中的每一帧都携带一条从请求方到响应方的消息。

    响应器随后可返回带有响应消息的PAYLOAD帧，在REQUEST_CHANNEL的情况下，请求方也可发送带有更多请求消息的PAYLOAD帧。

    当请求涉及消息流（如 Request-Stream 和 Channel）时，响应方必须尊重请求方的需求信号。需求以消息数量表示。初始需求在 REQUEST_STREAM 和 REQUEST_CHANNEL 帧中指定。后续需求通过 REQUEST_N 帧进行信号通知。

    每个端也可以通过 METADATA_PUSH 帧发送元数据通知，这些通知不针对任何单个请求，而是针对整个连接。

    消息格式

    RSocket 消息包含数据和元数据。元数据可用于发送路由、安全令牌等。数据和元数据的格式可能不同。每种类型的 MIME 类型在SETUP帧中声明，并适用于给定连接上的所有请求。

    虽然所有消息都可以包含元数据，但通常像路由这样的元数据是每次请求特有的，因此仅包含在请求中的第一条消息中，即带有以下帧之一：REQUEST_RESPONSE、REQUEST_STREAM、REQUEST_CHANNEL 或 REQUEST_FNF。

    协议扩展定义了应用程序中使用的通用元数据格式：

    • 复合元数据-- 多个独立格式的元数据条目。

    • 路由 — 请求的路由。

    Java 实现

    RSocket 的Java 实现构建在Project Reactor之上。TCP 和 WebSocket 传输层构建在Reactor Netty之上。作为 Reactive Streams 库，Reactor 简化了协议实现的复杂性。对于应用程序而言，使用带有声明式操作符和透明背压支持的Flux和Mono是自然的选择。

    RSocket Java 中的 API 故意设计得简洁而基础。它专注于协议功能，而将应用程序编程模型（例如 RPC 代码生成与其他方案）作为更高层且独立的问题来处理。

    主合约 io.rsocket.RSocket 通过 Mono 表示单个消息的承诺，Flux 表示消息流，以及 io.rsocket.Payload 表示包含对字节缓冲区中数据和元数据访问的实际消息，来建模四种请求交互类型。RSocket 合约是对称使用的。对于发起请求，应用程序会获得一个 RSocket 用于执行请求；对于响应，应用程序实现 RSocket 来处理请求。

    这并非旨在提供详尽的介绍。大部分情况下，Spring 应用程序无需直接使用其 API。然而，独立于 Spring 查看或实验 RSocket 可能很重要。RSocket Java 仓库包含多个示例应用，展示了其 API 和协议功能。

    Spring 支持

    spring-messaging 模块包含以下内容：

    • RSocketRequester — 用于通过带有数据元数据编码/解码的io.rsocket.RSocket发出请求的流畅式 API。

    • 注解响应器 — 用于响应的带有 @MessageMapping 和 @RSocketExchange 注解的处理方法。

    • RSocket 接口 — 作为请求者或响应者使用的 RSocket 服务声明，以带有@RSocketExchange方法的 Java 接口形式提供。

    spring-web 模块包含 RSocket 应用程序可能需要的 Encoder 和 Decoder 实现，例如 Jackson CBOR/JSON 以及 Protobuf。它还包含可用于高效路由匹配的 PathPatternParser。

    Spring Boot 2.2 支持在 TCP 或 WebSocket 上启动 RSocket 服务器，包括在 WebFlux 服务器中通过 WebSocket 暴露 RSocket 的选项。此外，还支持 RSocketRequester.Builder 和 RSocketStrategies 的客户端支持和自动配置。有关更多详细信息，请参阅 Spring Boot 参考中的 RSocket 部分。

    Spring Security 5.2 提供了对 RSocket 的支持。

    Spring Integration 5.2 提供入站和出站网关，用于与 RSocket 客户端和服务端进行交互。有关更多详细信息，请参阅 Spring Integration 参考手册。

    Spring Cloud Gateway 支持 RSocket 连接。

    RSocketRequester

    RSocketRequester 提供了一个流式 API 用于执行 RSocket 请求，接受并返回数据和元数据对象，而不是底层数据缓冲区。它可以对称地使用，既可用于客户端发起请求，也可用于服务端发起请求。

    客户端请求器

    要在客户端获取一个RSocketRequester，需要连接到服务器，这涉及发送带有连接设置的 RSocketSETUP 帧。RSocketRequester提供了一个构建器，用于准备一个io.rsocket.core.RSocketConnector，其中包括用于SETUP 帧的连接设置。

    这是使用默认设置连接的最基本方法：

    • Java

    • Kotlin

    RSocketRequester requester = RSocketRequester.builder().tcp("localhost", 7000);

URI url = URI.create("https://example.org:8080/rsocket");
RSocketRequester requester = RSocketRequester.builder().webSocket(url);
    val requester = RSocketRequester.builder().tcp("localhost", 7000)

URI url = URI.create("https://example.org:8080/rsocket");
val requester = RSocketRequester.builder().webSocket(url)

    上述内容不会立即建立连接。当发出请求时，会透明地建立共享连接并加以使用。

    连接设置

    RSocketRequester.Builder 提供以下功能以自定义初始 SETUP 帧：

    • dataMimeType(MimeType) — 设置连接上数据的 MIME 类型。

    • metadataMimeType(MimeType) — 设置连接上元数据的 MIME 类型。

    • setupData(Object) — 包含在 SETUP 中的数据。

    • setupRoute(String, Object…​) — 将元数据中的路由包含在 SETUP 中。

    • setupMetadata(Object, MimeType) — 要包含在 SETUP 中的其他元数据。

    对于数据，默认 MIME 类型源自第一个配置的 Decoder。对于元数据，默认 MIME 类型为复合元数据，它允许每个请求包含多个元数据值和 MIME 类型对。通常两者都不需要更改。

    SETUP 帧中的数据及元数据是可选的。在服务器端，可以使用@ConnectMapping方法来处理连接的启动以及SETUP帧的内容。元数据可用于连接级别的安全。

    注解响应器

    RSocket 响应器可以实现在 @MessageMapping 和 @ConnectMapping 方法中。@MessageMapping 方法处理单个请求，而 @ConnectMapping 方法处理连接级事件（设置和元数据推送）。注释的响应器在服务器端响应和客户端响应方面均得到对称支持。

    RSocketMessageHandler 默认支持组合和路由元数据。如果您需要切换到不同的 MIME 类型或注册额外的元数据 MIME 类型，可以设置其MetadataExtractor。

    您需要设置用于支持元数据和数据格式的Encoder和Decoder实例。您可能需要spring-web模块以获取编解码器实现。

    默认情况下，使用 SimpleRouteMatcher 通过 AntPathMatcher 匹配路由。我们建议从 spring-web 中集成 PathPatternRouteMatcher 以实现高效的路由匹配。RSocket 路由可以是分层的，但不是 URL 路径。两种路由匹配器默认都配置为使用 "." 作为分隔符，并且与 HTTP URL 不同，没有进行 URL 解码。

    @RSocketExchange

    作为 @MessageMapping 的替代方案，您也可以使用带有 @RSocketExchange 的方法来处理请求。此类方法声明在RSocket 接口上，可以通过 RSocketServiceProxyFactory 用作请求者，或由响应者实现。

    例如，作为响应器处理请求：

    • Java

    • Kotlin

    public interface RadarsService {

	@RSocketExchange("locate.radars.within")
	Flux<AirportLocation> radars(MapRequest request);
}

@Controller

	public Flux<AirportLocation> radars(MapRequest request) {
		// ...
	}

    interface RadarsService {

	@RSocketExchange("locate.radars.within")
	fun radars(request: MapRequest): Flow<AirportLocation>

@Controller
class RadarsController : RadarsService {

	override fun radars(request: MapRequest): Flow<AirportLocation> {
		// ...
	}
}

    @RSocketExchange 与 @MessageMapping 之间存在一些差异，因为前者需要同时适用于请求者和响应者。例如，虽然 @MessageMapping 可以声明为处理任意数量的路由，且每个路由都可以是一个模式（pattern），但 @RSocketExchange 必须声明为单个具体路由。此外，在支持的元数据方法参数方面也存在一些细微差异，有关支持参数的列表，请参阅 @MessageMapping 和 RSocket Interface。

    @RSocketExchange 可以在类型级别使用，以指定给定 RSocket 服务接口所有路由的公共前缀。

    @ConnectMapping

    @ConnectMapping 处理 RSocket 连接开头的 SETUP 帧，以及随后通过 METADATA_PUSH 帧推送的任何元数据通知，即 io.rsocket.RSocket 中的 metadataPush(Payload)。

    @ConnectMapping 方法支持与@MessageMapping相同的参数，但基于来自SETUP和METADATA_PUSH帧的元数据及数据。@ConnectMapping可以具有模式以将处理范围缩小到元数据中具有特定路由的连接；如果未声明任何模式，则所有连接均匹配。

    @ConnectMapping 方法不能返回数据，必须声明为返回 void 或 Mono<Void>。如果处理程序为新连接返回错误，则该连接会被拒绝。处理过程不得被挂起以向连接的 RSocketRequester 发起请求。有关详细信息，请参阅服务器请求器。

    MetadataExtractor

    响应者必须解释元数据。组合元数据允许独立格式的元数据值（例如，用于路由、安全、跟踪），每个值都有其自己的 mime 类型。应用程序需要一种方法来配置支持的元数据 mime 类型，以及一种方法来访问提取的值。

    MetadataExtractor 是一个接口，用于接收序列化的元数据并返回解码后的名称 - 值对，这些对随后可以像通过名称访问的标头一样被访问，例如在注释的处理程序方法中通过 @Header 进行访问。

    DefaultMetadataExtractor 可以接收用于解码元数据的 Decoder 实例。开箱即用，它支持 "message/x.rsocket.routing.v0"，将其解码为 String 并保存在 "route" 键下。对于任何其他 mime 类型，您需要提供一个 Decoder 并按如下方式注册该 mime 类型：

    • Java

    • Kotlin

    DefaultMetadataExtractor extractor = new DefaultMetadataExtractor(metadataDecoders);
extractor.metadataToExtract(fooMimeType, Foo.class, "foo");
    import org.springframework.messaging.rsocket.metadataToExtract

val extractor = DefaultMetadataExtractor(metadataDecoders)
extractor.metadataToExtract<Foo>(fooMimeType, "foo")

    RSocket 接口

    Spring Framework 允许您将 RSocket 服务定义为带有 @RSocketExchange 方法的 Java 接口。您可以将该接口传递给 RSocketServiceProxyFactory 以创建一个代理，该代理通过 RSocketRequester 执行请求。您也可以实现该接口作为响应器来处理请求。

    首先，使用带有@RSocketExchange方法的接口创建接口：

    interface RadarService {

	@RSocketExchange("radars")
	Flux<AirportLocation> getRadars(@Payload MapRequest request);

	// more RSocket exchange methods...

}

    现在您可以创建一个代理，在调用方法时执行请求：

    RSocketRequester requester = ... ;
RSocketServiceProxyFactory factory = RSocketServiceProxyFactory.builder(requester).build();

RadarService service = factory.createClient(RadarService.class);

    您也可以实现接口作为响应器来处理请求。 参见 注解响应器。

    方法参数

    带注释的 RSocket 交换方法支持灵活的方法签名，其包含以下方法参数：

    方法参数 描述

    @DestinationVariable

    添加一个路由变量，与@RSocketExchange注解中的路由一起传递给RSocketRequester，以扩展路由中的模板占位符。该变量可以是 String 或任何 Object，随后通过toString()进行格式化。

    @Payload

    设置请求的输入负载。这可以是一个具体值，也可以是任何可以通过 ReactiveAdapterRegistry 适配为 Reactive Streams Publisher 的值生产者。除非将 required 属性设置为 false，或者参数被标记为可选（由 MethodParameter#isOptional 确定），否则必须提供负载。

    Object，如果后面跟着 MimeType

    输入负载中元数据条目的值。只要下一个参数是元数据条目 MimeType，该值可以是任何 Object。该值可以是一个具体值，也可以是任何能够生成单个值的对象，该对象可以通过 ReactiveAdapterRegistry 适配为 Reactive Streams Publisher。

    MimeType

    元数据条目的 MimeType。前一个方法参数预期为元数据值。

    返回值

    经过注解的 RSocket 交换方法支持返回具体值，或任何可通过 ReactiveAdapterRegistry 适配为 Reactive Streams Publisher 的值生产者。

    默认情况下，具有同步（阻塞）方法签名的 RSocket 服务方法的行为取决于底层 RSocket ClientTransport 的响应超时设置以及 RSocket 保活设置。RSocketServiceProxyFactory.Builder 确实提供了一个blockTimeout选项，允许您配置等待响应的最大阻塞时间，但我们建议在 RSocket 级别配置超时值以获得更灵活的控制。
