    声明 Advice

    Advice 与切点表达式相关联，并在匹配该切点的执行之前、之后或围绕方法执行时运行。切点表达式可以是 内联切点，也可以是对 命名切点 的引用。

    前置通知

    您可以在切面中使用 @Before 注解声明前置通知。

    以下示例使用了一个内联切面表达式。

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Before;

@Aspect
public class BeforeExample {

	@Before("execution(* com.xyz.dao.*.*(..))")
	public void doAccessCheck() {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.Before

@Aspect
class BeforeExample {

	@Before("execution(* com.xyz.dao.*.*(..))")
	fun doAccessCheck() {
		// ...
	}
}

    如果我们使用命名切点，可以重写前面的示例如下：

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Before;

@Aspect
public class BeforeExample {

	@Before("com.xyz.CommonPointcuts.dataAccessOperation()")
	public void doAccessCheck() {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.Before

@Aspect
class BeforeExample {

	@Before("com.xyz.CommonPointcuts.dataAccessOperation()")
	fun doAccessCheck() {
		// ...
	}
}

    返回后通知

    在匹配的方法执行正常返回后，会运行 Advice。您可以使用 @AfterReturning 注解来声明它。

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.AfterReturning;

@Aspect
public class AfterReturningExample {

	@AfterReturning("execution(* com.xyz.dao.*.*(..))")
	public void doAccessCheck() {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.AfterReturning

@Aspect
class AfterReturningExample {

	@AfterReturning("execution(* com.xyz.dao.*.*(..))")
	fun doAccessCheck() {
		// ...
	}
}
    您可以有多个建议声明（以及其他成员），全部位于同一个切面中。这些示例中仅显示单个建议声明，以便集中说明每个声明的效果。

    有时，您需要在建议体中访问实际返回的值。您可以使用将返回值绑定到该值的@AfterReturning形式来获取此访问权限，如下例所示：

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.AfterReturning;

@Aspect
public class AfterReturningExample {

	@AfterReturning(
		pointcut="execution(* com.xyz.dao.*.*(..))",
		returning="retVal")
	public void doAccessCheck(Object retVal) {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.AfterReturning

@Aspect
class AfterReturningExample {

	@AfterReturning(
		pointcut = "execution(* com.xyz.dao.*.*(..))",
		returning = "retVal")
	fun doAccessCheck(retVal: Any?) {
		// ...
	}
}

    returning 属性中使用的名称必须对应于 advice 方法中的参数名称。当方法执行返回时，返回值将作为对应的参数值传递给 advice 方法。returning 子句还将匹配限制为仅返回指定类型（在此情况下为 Object，可匹配任何返回值）的方法执行。

    请注意，在使用返回后通知（after returning advice）时，无法返回一个完全不同的引用。

    后置异常通知

    在匹配的方法执行因抛出异常而退出后，会运行建议。您可以使用 @AfterThrowing 注解来声明它，如下例所示：

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.AfterThrowing;

@Aspect
public class AfterThrowingExample {

	@AfterThrowing("execution(* com.xyz.dao.*.*(..))")
	public void doRecoveryActions() {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.AfterThrowing

@Aspect
class AfterThrowingExample {

	@AfterThrowing("execution(* com.xyz.dao.*.*(..))")
	fun doRecoveryActions() {
		// ...
	}
}

    通常，您希望建议仅在抛出特定类型的异常时运行，并且通常需要在建议体中访问抛出的异常。您可以使用 throwing 属性来限制匹配（如需要——否则请使用 Throwable 作为异常类型）并将抛出的异常绑定到建议参数。以下示例展示了如何操作：

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.AfterThrowing;

@Aspect
public class AfterThrowingExample {

	@AfterThrowing(
		pointcut="execution(* com.xyz.dao.*.*(..))",
		throwing="ex")
	public void doRecoveryActions(DataAccessException ex) {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.AfterThrowing

@Aspect
class AfterThrowingExample {

	@AfterThrowing(
		pointcut = "execution(* com.xyz.dao.*.*(..))",
		throwing = "ex")
	fun doRecoveryActions(ex: DataAccessException) {
		// ...
	}
}

    throwing 属性中使用的名称必须对应于 advice 方法中的参数名称。当方法执行因抛出异常而退出时，该异常将作为相应的参数值传递给 advice 方法。throwing 子句还将匹配限制为仅抛出指定类型（在本例中为 DataAccessException）异常的方法执行。

    注意，@AfterThrowing 并不表示通用的异常处理回调。具体来说，@AfterThrowing 通知方法仅应接收来自连接点（用户声明的目标方法）本身的异常，而不应来自伴随的 @After/@AfterReturning 方法。

    After (Finally) Advice

    在匹配的方法执行退出后（最终）运行 Advice。它通过使用 @After 注解声明。After Advice 必须准备好处理正常和异常返回条件。它通常用于释放资源等目的。以下示例展示了如何使用 After Finally Advice：

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.After;

@Aspect
public class AfterFinallyExample {

	@After("execution(* com.xyz.dao.*.*(..))")
	public void doReleaseLock() {
		// ...
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.After

@Aspect
class AfterFinallyExample {

	@After("execution(* com.xyz.dao.*.*(..))")
	fun doReleaseLock() {
		// ...
	}
}

    请注意，AspectJ 中的@After建议被定义为“后 finally 建议”，类似于 try-catch 语句中的 finally 块。它将在任何结果下被调用，包括连接点（用户声明的目标方法）的正常返回或抛出的异常，而不同于仅适用于成功正常返回的@AfterReturning。

    环绕建议

    最后一种建议是 环绕 建议。环绕建议在匹配方法的执行过程中“环绕”运行。它有机会在方法运行之前和之后执行工作，并决定方法何时、如何甚至是否实际运行。如果您需要在线程安全的方式下共享方法执行前后的状态——例如启动和停止计时器——通常会使用环绕建议。

    始终使用满足要求的最弱形式的建议。

    例如，如果before切面足以满足您的需求，则不要使用around切面。

    Around 建议通过用 @Around 注解标记一个方法来声明。该方法应声明 Object 作为其返回类型，且该方法的第一个参数必须是 ProceedingJoinPoint 类型。在建议方法的主体中，您必须在 ProceedingJoinPoint 上调用 proceed()，以便运行底层方法。不带参数地调用 proceed() 将导致调用者的原始参数在底层方法被调用时作为参数传入。对于高级用例，proceed() 方法有一个接受参数数组 (Object[]) 的重载变体。数组中的值将在底层方法被调用时用作其参数。

    当使用 Object[] 调用 proceed 时，其行为与由 AspectJ 编译器编译的 around 建议中 proceed 的行为略有不同。对于使用传统 AspectJ 语言编写的 around 建议，传递给 proceed 的参数数量必须与传递给 around 建议的参数数量相匹配（而不是底层连接点接受的参数数量），并且在给定参数位置传递给 proceed 的值会替换绑定到该值的实体在连接点处的原始值（如果现在这听起来没有意义，请不要担心）。

    Spring 采用的方法更简单，也更符合其基于代理、仅执行一次的语义。您只需在针对 Spring 编译使用 @AspectJ 编写的切面，并在使用 AspectJ 编译器及织入器时配合参数调用 proceed 的情况下，才需要了解这一差异。存在一种编写此类切面的方法，可实现与 Spring AOP 和 AspectJ 的 100% 兼容，相关内容将在下文关于通知参数的部分中讨论。

    around 建议返回的值是方法调用者看到的返回值。例如，一个简单的缓存切面如果有缓存，可以返回缓存中的值；否则，可以调用 proceed()（并返回该值）。请注意，proceed 可能在 around 建议的体内被调用一次、多次，或者根本不调用。这些都是合法的。

    如果您将环绕建议方法的返回类型声明为 void，则始终会向调用者返回 null，从而实际上忽略了任何 proceed() 调用的结果。因此，建议环绕建议方法声明 Object 作为返回类型。即使底层方法的返回类型为 void，建议方法通常也应返回 proceed() 调用的返回值。不过，根据具体用例，建议方法还可以选择性地返回缓存值、包装值或其他值。

    下面的示例展示了如何使用 around 建议：

    • Java

    • Kotlin

    import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.ProceedingJoinPoint;

@Aspect
public class AroundExample {

	@Around("execution(* com.xyz..service.*.*(..))")
	public Object doBasicProfiling(ProceedingJoinPoint pjp) throws Throwable {
		// start stopwatch
		Object retVal = pjp.proceed();
		// stop stopwatch
		return retVal;
	}
}
    import org.aspectj.lang.annotation.Aspect
import org.aspectj.lang.annotation.Around
import org.aspectj.lang.ProceedingJoinPoint

@Aspect
class AroundExample {

	@Around("execution(* com.xyz..service.*.*(..))")
	fun doBasicProfiling(pjp: ProceedingJoinPoint): Any? {
		// start stopwatch
		val retVal = pjp.proceed()
		// stop stopwatch
		return retVal
	}
}

    Advice 参数

    Spring 提供完全类型化的建议，这意味着您可以在建议签名中声明所需的参数（正如我们在返回和抛出示例中看到的），而不必总是处理 Object[] 数组。我们将在本节稍后部分介绍如何让参数和其他上下文值对建议体可用。首先，我们来看一下如何编写通用建议，以获取当前建议的方法信息。

    访问当前JoinPoint

    任何切面方法都可以声明一个类型为org.aspectj.lang.JoinPoint的第一个参数。请注意，环绕切面必须声明一个类型为ProceedingJoinPoint的第一个参数，它是JoinPoint的子类。

    JoinPoint 接口提供了一些有用的方法：

    • getArgs()：返回方法参数。

    • getThis()：返回代理对象。

    • getTarget()：返回目标对象。

    • getSignature()：返回正在被建议的方法的描述。

    • toString()：打印被建议方法的有用描述。

    有关更多详细信息，请参阅 javadoc。

    向 Advice 传递参数

    我们已经看到了如何绑定返回值或异常值（使用 after returning 和 after throwing 通知）。若要使参数值对通知体可用，可以使用 args 的绑定形式。如果在 args 表达式中使用参数名代替类型名，则在调用通知时，对应参数的值将作为参数值传递。示例将使这一点更加清晰。 假设您希望建议执行以 Account 对象作为第一个参数的 DAO 操作，并且需要在通知体中访问该账户。您可以编写如下代码：

    • Java

    • Kotlin

    @Before("execution(* com.xyz.dao.*.*(..)) && args(account,..)")
public void validateAccount(Account account) {
	// ...
}
    @Before("execution(* com.xyz.dao.*.*(..)) && args(account,..)")
fun validateAccount(account: Account) {
	// ...
}

    args(account,..) 切点表达式部分有两个作用。首先，它将匹配限制为仅针对那些方法至少有一个参数且传递给该参数的参数是 Account 实例的方法执行。其次，它通过 account 参数将实际的 Account 对象提供给 advice。

    另一种写法是声明一个在匹配连接点时“提供”Account 对象值的切入点，然后在 Advice 中引用该命名切入点。其代码如下所示：

    • Java

    • Kotlin

    @Pointcut("execution(* com.xyz.dao.*.*(..)) && args(account,..)")
private void accountDataAccessOperation(Account account) {}

@Before("accountDataAccessOperation(account)")
public void validateAccount(Account account) {
	// ...
}
    @Pointcut("execution(* com.xyz.dao.*.*(..)) && args(account,..)")
private fun accountDataAccessOperation(account: Account) {
}

@Before("accountDataAccessOperation(account)")
fun validateAccount(account: Account) {
	// ...
}

    有关更多详细信息，请参阅 AspectJ 编程指南。

    代理对象 (this)、目标对象 (target) 和注解 (@within、@target、@annotation 以及 @args) 都可以以类似的方式进行绑定。下一组示例展示了如何匹配带有 @Auditable 注解的方法的执行并提取审计代码：

    下面显示了 @Auditable 注解的定义：

    • Java

    • Kotlin

    @Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Auditable {
	AuditCode value();
}
    @Retention(AnnotationRetention.RUNTIME)
@Target(AnnotationTarget.FUNCTION)
annotation class Auditable(val value: AuditCode)

    以下是与执行@Auditable方法匹配的 Advice：

    • Java

    • Kotlin

    @Before("com.xyz.Pointcuts.publicMethod() && @annotation(auditable)") (1)
public void audit(Auditable auditable) {
	AuditCode code = auditable.value();
	// ...
}
    1 引用了在组合点切面表达式中定义的名为publicMethod的点切面。 
    @Before("com.xyz.Pointcuts.publicMethod() && @annotation(auditable)") (1)
fun audit(auditable: Auditable) {
	val code = auditable.value()
	// ...
}
    1 引用了在组合点切面表达式中定义的名为publicMethod的点切面。

    AOP 通知参数和泛型

    Spring AOP 可以处理类声明和方法参数中使用的泛型。假设您有一个如下所示的泛型类型：

    • Java

    • Kotlin

    public interface Sample<T> {
	void sampleGenericMethod(T param);
	void sampleGenericCollectionMethod(Collection<T> param);
}
    interface Sample<T> {
	fun sampleGenericMethod(param: T)
	fun sampleGenericCollectionMethod(param: Collection<T>)
}

    您可以通过将建议参数绑定到希望拦截方法的参数类型，从而限制对方法类型的拦截：

    • Java

    • Kotlin

    @Before("execution(* ..Sample+.sampleGenericMethod(*)) && args(param)")
public void beforeSampleMethod(MyType param) {
	// Advice implementation
}
    @Before("execution(* ..Sample+.sampleGenericMethod(*)) && args(param)")
fun beforeSampleMethod(param: MyType) {
	// Advice implementation
}

    这种方法不适用于泛型集合。因此，您不能按如下方式定义切面：

    • Java

    • Kotlin

    @Before("execution(* ..Sample+.sampleGenericCollectionMethod(*)) && args(param)")
public void beforeSampleMethod(Collection<MyType> param) {
	// Advice implementation
}
    @Before("execution(* ..Sample+.sampleGenericCollectionMethod(*)) && args(param)")
fun beforeSampleMethod(param: Collection<MyType>) {
	// Advice implementation
}

    要实现这一点，我们必须检查集合中的每个元素，这并不合理，因为我们也无法决定如何处理null值。要达到类似的效果，您需要将参数类型指定为Collection<?>，并手动检查元素的类型。

    确定参数名称

    建议调用中的参数绑定依赖于将切面表达式中使用的名称与建议和切面方法签名中声明的参数名称进行匹配。

    本节将 argument 和 parameter 这两个术语互换使用，因为 AspectJ API 将参数名称称为参数名。

    Spring AOP 使用以下 ParameterNameDiscoverer 实现来确定参数名称。每个发现器都会被给予一次发现参数名称的机会，第一个成功的发现器将胜出。如果所有已注册的实现都无法确定参数名称，将抛出异常。

    AspectJAnnotationParameterNameDiscoverer

    使用用户在相应的 advice 或切面注解中通过 argNames 属性明确指定的参数名称。有关详细信息，请参阅显式参数名称。

    KotlinReflectionParameterNameDiscoverer

    使用 Kotlin 反射 API 来确定参数名称。仅当类路径中存在此类 API 时，才会使用该发现器。

    StandardReflectionParameterNameDiscoverer

    使用标准的java.lang.reflect.ParameterAPI 来确定参数名称。要求代码使用-parameters标志进行编译，以便javac支持。这是 Java 8+ 的推荐方法。

    AspectJAdviceParameterNameDiscoverer

    从切点表达式、returning 和 throwing 子句中推断参数名称。有关所用算法的详细信息，请参阅javadoc。

    显式参数名称

    @AspectJ 的 advice 和 pointcut 注解有一个可选的 argNames 属性，您可以使用它来指定被注解方法的参数名称。

    如果已通过 AspectJ 编译器（ajc）编译了 @AspectJ 切面，即使没有调试信息，您也不需要添加 argNames 属性，因为编译器会保留所需的信息。

    同样，如果已使用带有-parameters标志的javac编译了@AspectJ 切面，则无需添加argNames属性，因为编译器会保留所需的信息。

    以下示例展示了如何使用argNames属性：

    • Java

    • Kotlin

    @Before(
	value = "com.xyz.Pointcuts.publicMethod() && target(bean) && @annotation(auditable)", (1)
	argNames = "bean,auditable") (2)
public void audit(Object bean, Auditable auditable) {
	AuditCode code = auditable.value();
	// ... use code and bean
}
    1 引用了在组合点切面表达式中定义的名为publicMethod的点切面。
    2 声明bean和auditable为参数名称。 
    @Before(
	value = "com.xyz.Pointcuts.publicMethod() && target(bean) && @annotation(auditable)", (1)
	argNames = "bean,auditable") (2)
fun audit(bean: Any, auditable: Auditable) {
	val code = auditable.value()
	// ... use code and bean
}
    1 引用了在组合点切面表达式中定义的名为publicMethod的点切面。
    2 声明bean和auditable为参数名称。

    如果第一个参数的类型为 JoinPoint、ProceedingJoinPoint 或 JoinPoint.StaticPart，您可以从 argNames 属性的值中省略该参数的名称。例如，如果您修改前面的 advice 以接收 join point 对象，则 argNames 属性无需包含它：

    • Kotlin

	// ... use code, bean, and jp

    2 声明bean和auditable为参数名称。

	value = "com.xyz.Pointcuts.publicMethod() && target(bean) && @annotation(auditable)", (1)

public void audit(JoinPoint jp) {
	// ... use jp

	// ... use jp

    带参数的继续执行

    我们之前提到过，将描述如何编写一个带参数的 proceed 调用，使其在 Spring AOP 和 AspectJ 之间保持一致。解决方案是确保 advice 的签名按顺序绑定每个方法参数。以下示例展示了如何实现这一点：

    • Java

    • Kotlin

    @Around("execution(List<Account> find*(..)) && " +
		"com.xyz.CommonPointcuts.inDataAccessLayer() && " +
		"args(accountHolderNamePattern)") (1)
public Object preProcessQueryPattern(ProceedingJoinPoint pjp,
		String accountHolderNamePattern) throws Throwable {
	String newPattern = preProcess(accountHolderNamePattern);
	return pjp.proceed(new Object[] {newPattern});
}
    1 引用了在共享命名切面定义中定义的名为inDataAccessLayer的切入点。 
    @Around("execution(List<Account> find*(..)) && " +
		"com.xyz.CommonPointcuts.inDataAccessLayer() && " +
		"args(accountHolderNamePattern)") (1)
fun preProcessQueryPattern(pjp: ProceedingJoinPoint,
						accountHolderNamePattern: String): Any? {
	val newPattern = preProcess(accountHolderNamePattern)
	return pjp.proceed(arrayOf<Any>(newPattern))
}
    1 引用了在共享命名切面定义中定义的名为inDataAccessLayer的切入点。

    在许多情况下，您无论如何都会执行此绑定（如前面的示例所示）。

    通知排序

    当多个切面建议都希望在同一个连接点执行时，Spring AOP 遵循与 AspectJ 相同的优先级规则来确定建议的执行顺序。最高优先级的建议首先“进入”（因此，给定两个 before 建议，优先级最高的那个先运行）。从连接点“退出”时，最高优先级的建议最后运行（因此，给定两个 after 建议，优先级最高的那个将第二个运行）。

    当两个定义在不同切面中的建议都需要在同一个连接点运行时，除非另有指定，否则执行顺序是未定义的。您可以通过指定优先级来控制执行顺序。这是通过 Spring 的常规方式实现的：要么在切面类中实现 org.springframework.core.Ordered 接口，要么使用 @Order 注解对其进行标注。给定两个切面，返回 Ordered.getOrder()（或注解值）较低值的切面具有更高的优先级。

    特定切面的每种不同通知类型在概念上都应直接应用于连接点。因此，@AfterThrowing 通知方法不应从配套的 @After/@AfterReturning 方法接收异常。

    定义在同一@Aspect类中且需要在同一连接点运行的建议方法，根据其建议类型按以下顺序分配优先级（从高到低）：@Around、@Before、@After、@AfterReturning、@AfterThrowing。然而请注意，同一切面中的@After建议方法实际上会在任何@AfterReturning或@AfterThrowing建议方法之后被调用，这遵循了 AspectJ 针对@After的“后置最终建议”语义。

    当同一类型的两个切面建议（例如，两个@After 建议方法）定义在同一个@Aspect类中，且都需要在同一连接点运行时，其执行顺序是未定义的（因为无法通过反射获取 javac 编译类的源代码声明顺序）。请考虑将此类建议方法合并为每个连接点在每个@Aspect类中的一个建议方法，或者重构这些建议部分到单独的@Aspect类中，以便您可以通过Ordered或@Order在切面级别对其进行排序。
